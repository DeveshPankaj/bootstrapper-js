"Dense" and "fully connected" name the same layer (every output is a weighted sum of every input, plus a bias) — different frameworks just call it different things, so there's one button for it here.

Training

Each batch: play this many games with the current network, keep only the moves from games with a positive total reward (below), deduplicated so the same board+action pair only trains once per batch even if several games passed through it, then fit that filtered set as one supervised training pass before playing the next batch. A batch with no positive-reward games trains on nothing and just moves on to the next one. A snake looping without eating is killed after "idle steps" ticks since its last food — defaults to the board's box count (14×14 = 196).

Reward weights

Summed across every step of a game (food is worth a fixed +10 internally, not a slider) to get that game's total reward — the "final result" that decides whether a game's moves are used for training at all. Distance reward/away penalty apply per step of Manhattan distance closed/opened; slow-path fires once a game takes longer than the gap between consecutive food spawns; wall/tail-hit fire once on death by that cause; curl fires when the head makes little net progress over a short rolling window of steps.

About

The board is fed in as a 3-channel volume (channel 0: board + food, channel 1: snake body, channel 2: snake head) — 3×14×14 voxels with 1 input channel. Conv3D layers slide a k×k×k kernel across all three axes (depth included) with same-padding, so depth stays 3 throughout the stack while the channel count changes to each layer's filter count. After the last Conv3D layer the volume is flattened into Dense layers, ending in a fixed Dense(3, linear) output; softmax turns those 3 logits into a straight/left/right probability distribution.

This is trained by real backpropagation, but as a batch self-imitation / Monte-Carlo policy-improvement method (a strict variant of the Cross-Entropy Method), not textbook temporal-difference Q-learning — there's no per-step bootstrapped target here. Each batch: (1) play "games per batch" full games, sampling each move from the network's own softmax output (so exploration comes from the policy's own uncertainty, no separate exploration schedule needed) and summing every step's reward into that game's total; (2) throw away every move from a game whose total reward wasn't positive — only winning games teach anything this batch — then, from what's left, keep only the first occurrence of each distinct (board, action) pair so a common transition seen across several games doesn't dominate the training pass, and give every surviving move a clean one-hot target on the action actually taken (no games are being pushed away from an action, only reinforced toward one, since only wins reach this stage); (3) fit the whole shuffled, filtered set of (board, target) pairs as one supervised softmax-cross-entropy training pass — whose gradient at the output layer has the standard closed form predicted probabilities − target — backpropagated through every Dense and Conv3D layer (hand-derived, not autodiff) with plain SGD at the learning rate above, then the next batch is played with the freshly-updated network. A batch with no winning games trains on nothing and just moves on. Rollout is rendered live; the (typically much smaller, post-filtering) training pass over the batch isn't, since there's no game to show — the run status line below the Start button reports which phase is active.

The network's weights are checkpointed to this app's own data dir after every batch and reloaded automatically next time this window opens (only the latest checkpoint is kept, not a history), along with all the settings above. Editing the architecture starts a fresh randomly-initialized network — and a fresh checkpoint — next time you press Start.
